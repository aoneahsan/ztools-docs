# html-entities

HTML entities are escape sequences that represent characters which are either reserved in HTML (`&lt;`, `&gt;`, `&`), invisible (non-breaking space), or hard to type directly (©, ™, ←, ✓). The ZTools HTML Entities tool is a comprehensive reference and converter: search the full HTML5 named entity table by name, number, or character; convert any character to its named, decimal numeric (`&#169;`), or hex numeric (`&#xA9;`) entity form; and decode any entity back to its character. Built-in copy buttons make it fast to look up `→` or `©` and paste the right entity into your HTML.

## Use cases

### Inserting special characters into HTML without typing them

Need an em-dash (—), copyright symbol (©), or arrow (→) in your HTML? Search the entity table, click Copy, paste. Faster than memorizing entity names or hunting through Unicode tables.

### Identifying mystery entities in HTML source

You see `&#8594;` in a stranger's HTML and wonder what it renders as. Paste into the decoder; the tool shows the character (→) and its name (`&rarr;`).

### Standardizing entity style across a codebase

Some files use `&copy;`, others use `&#169;`, others use `&#xA9;` — all valid, all equivalent. Convert all to one style for consistency in code review and grep.

### Building or debugging an entity-aware text editor

When implementing rich-text features (like Notion-style "type `--` and get `—`"), the entity table tells you which character → entity mappings to support. The reference is built from the official HTML5 spec.

## Frequently asked questions

<details>
<summary>**When do I need to use HTML entities?**</summary>

Always for `&`, `&lt;`, `&gt;`, `"`, `'` inside HTML body or attributes. Optional for other characters in modern UTF-8 documents — write them literally. Use entities for non-typeable characters (←, ✓) or when sending HTML through systems that may corrupt UTF-8.

</details>

<details>
<summary>**What's the difference between named and numeric entities?**</summary>

Named entities like `&copy;` are human-readable but limited to ~2,200 characters in HTML5. Numeric entities like `&#169;` work for any Unicode code point (1.1M+ characters). Named entities are slightly shorter for common chars; numeric entities are universal.

</details>

<details>
<summary>**Are HTML entities case-sensitive?**</summary>

Yes — `&Copy;` and `&copy;` are different entities (uppercase Copy is a math symbol; lowercase is the © character). When in doubt, copy from a reference table.

</details>

<details>
<summary>**Do I need to use entities for emoji?**</summary>

No — emoji are plain UTF-8 characters. Save your file as UTF-8 (the modern default), declare `&lt;meta charset="UTF-8"&gt;`, and emoji render directly. Entity-encoding emoji wastes bytes.

</details>

<details>
<summary>**How many HTML entities exist?**</summary>

HTML5 defines ~2,200 named entities. Numeric entities can address all 1.1M+ Unicode code points.

</details>

<details>
<summary>**Why might my entity not render?**</summary>

Most common cause: typo in the name (`&abcd;` is invalid). Other causes: missing semicolon, browser caching, or an XHTML doctype that requires strict syntax.

</details>

## Tips

- Prefer numeric entities for non-Latin scripts (more reliable across legacy parsers).
- Always include the trailing semicolon — some parsers tolerate its absence, but it's a syntax error per spec.
- For modern UTF-8 documents, only encode `&lt;`, `&gt;`, `&`, `"`, `'` — write everything else as literal characters.
- Use named entities for documentation's sake (`&euro;` is readable; `&#8364;` is opaque).
