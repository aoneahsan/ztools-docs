# JSON Tree Viewer

A JSON tree viewer renders a JSON document as a hierarchical interactive tree — each object and array becomes a collapsible node, primitives display with type indicators (string, number, boolean, null) — making deeply nested API responses and configuration files navigable instead of having to scroll through thousands of lines of formatted JSON. The ZTools JSON Tree Viewer handles megabytes of JSON, supports collapse-all and expand-to-depth (1, 2, 3), highlights matched values when searching, shows the path to any node, and renders even large arrays performantly using virtualization so a 100,000-element array doesn't freeze the browser.

## Use cases

### Exploring a complex API response

A 5,000-line REST response. Collapse to top level, expand only the branches that matter. Find the field you need in seconds instead of scrolling for minutes.

### Inspecting a Firestore document export

Documents have nested maps and arrays of maps. The tree view makes the structure explicit; the formatted-text view buries it in indentation.

### Debugging deeply nested config files

A 200-key application config. Search for "timeout" — every match highlighted. Each match has its full path shown so you know which subsystem owns it.

### Teaching JSON structure

Visual tree clearly shows object vs array, key vs value, types of each leaf. Easier for learners than dense text.

## How it works

1. **Paste your JSON** — Validates first; malformed JSON shows an error with line/column. After parsing, the tree appears.
2. **Expand and collapse nodes** — Click triangles next to objects/arrays. Buttons for "expand all", "collapse all", "expand to depth N".
3. **Inspect each node** — Type indicators (string, number, boolean, null, array, object) on each value. Array sizes shown ([12 items]) so you don't expand huge arrays accidentally.
4. **Search and copy paths** — Type a search term; matches highlight in the tree. Click any node to copy its JSONPath to your clipboard.
5. **Switch to text view** — Toggle between tree and pretty-printed text. Same data, different rendering — useful for copying full subtrees or for diff comparison.

## Frequently asked questions

<details>
<summary>**How does this differ from a JSON formatter?**</summary>

A formatter pretty-prints text. A tree viewer renders structure interactively — you can collapse nodes, see types, navigate hierarchies. Use a formatter for diff-friendly text; a viewer for exploration.

</details>

<details>
<summary>**Can it handle very large JSON files?**</summary>

Yes — virtualization renders only visible nodes. Megabytes of JSON work; gigabytes need a streaming parser. For massive files, consider jq or a dedicated viewer.

</details>

<details>
<summary>**Does it support drag-and-drop file upload?**</summary>

Yes — drop a .json file onto the tree to load it. File contents stay in your browser; nothing is uploaded.

</details>

<details>
<summary>**Will the tree show me hidden values like __proto__?**</summary>

No — the viewer shows only the document's actual JSON content, not JavaScript-specific properties. Internal browser objects don't show up.

</details>

<details>
<summary>**Can I edit values in the tree?**</summary>

This viewer is read-only. For inline editing, use a JSON editor with an edit toggle. Read-only avoids accidental edits when you're just exploring.

</details>

## Tips

- For unfamiliar data, "expand to depth 2" is often the sweet spot — enough structure visible without drowning.
- When sharing a finding with teammates, copy the path to a value rather than the value itself — pinpoints the structure.
- Search is faster than scrolling for finding a value in a 1,000-key document.
- Switch between tree and text view to suit the task — explore in tree, copy/diff in text.
