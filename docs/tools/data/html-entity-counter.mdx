# html-entity-counter

HTML entities are escape sequences for special characters: &amp; for &, &lt; for &lt;, &gt; for &gt;, &quot; for ", &#x2603; for ☃. Counting entities is useful for HTML migration audits ("did we escape everything?"), email-template inspection, and security review (are &lt;script&gt; tags being properly entity-escaped?). The ZTools HTML Entity Counter parses any text, lists every named and numeric entity it finds with frequency, and shows the resolved character for each.

<ToolCTA toolId="html-entity-counter" toolName="html-entity-counter" />

## Use cases

### Audit a template for escape consistency

A template uses &amp; in some places and & in others. Counter highlights the mismatch.

### Check user-generated content for unescaped special chars

After a sanitiser runs, count entities. Too few = sanitiser missed cases. Too many = over-escaping.

### Migrate from HTML to Markdown

Markdown rarely needs entities. Counter shows what to convert back to plain chars.

### Decode hex / decimal numeric entities

&#x2603; → ☃ (snowman). Counter shows the resolved char alongside the count.

## How it works

1. **Paste HTML / text** — Any text containing entities.
2. **Scan** — Regex matches &name; (named), &#NNN; (decimal), &#xHHHH; (hex). Each match decoded.
3. **Count** — Frequency table per unique entity. Top entities highlighted.
4. **Display** — Table: entity, decoded char, count. Plus total entity count and total chars.

## Frequently asked questions

<details>
<summary>**Doubly-encoded entities?**</summary>

When &amp;amp; appears, it means a sanitiser ran twice. Tool flags suspicious patterns like &amp;quot; (escape of &quot;).

</details>

<details>
<summary>**Numeric vs named entities?**</summary>

Named (&copy;, &mdash;) more readable; numeric (&#169;, &#8212;) more universal. Tool decodes both.

</details>

## Tips

- For HTML output, use named entities for readability — &copy; beats &#169;.
- For email HTML, more conservative — use entities for any non-ASCII char to avoid encoding mismatches.
- For Markdown migration, decode all entities first — Markdown handles plain chars natively.
- Doubly-encoded entities (&amp;amp;) are a security smell — investigate the sanitisation pipeline.
