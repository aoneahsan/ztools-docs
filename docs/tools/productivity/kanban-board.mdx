# kanban-board

A Kanban board is a workflow visualisation tool with a column per workflow stage (typically To Do / In Progress / Done) and a card per task, where you drag cards between columns as work progresses — letting you see exactly how much work is in flight, where it is stuck, and what is finished, all at one glance. The ZTools Kanban Board runs entirely in the browser, supports custom columns, drag-and-drop card movement, due dates, priority labels, optional WIP limits, and persists all data in browser local storage so closing the tab does not lose your board.

## Use cases

### Personal weekly planning

Three columns (This Week / Today / Done). Sunday: list everything for the week in This Week. Each morning: pull 3-5 cards into Today. Drag to Done as you finish — instant visibility into pace.

### Side project tracking

Backlog / Up Next / In Progress / Review / Done. Side projects stall without structure; the board acts as a low-overhead substitute for a Jira board.

### Family / household tasks

Per-person swim lanes or a shared family board. Everyone sees what is in flight; nothing falls through the cracks; Sunday review is concrete.

### Course assignment tracking

Assigned / Reading / Drafting / Submitting / Submitted. For students juggling 4-5 courses with overlapping due dates, the board surfaces the most urgent items.

## How it works

1. **Set up columns** — Default: To Do / Doing / Done. Customise to your workflow (e.g. Backlog / Up Next / In Progress / Review / Done).
2. **Add cards** — One card = one task. Title, optional description, due date, priority label.
3. **Drag between columns** — Pick up a card with mouse / touch, drop in the new column. Movement is instant and persisted.
4. **(Optional) Set WIP limits** — Cap how many cards can sit in In Progress (e.g. max 3). Forces finishing before starting more — the core Kanban discipline.
5. **Review and clean up** — Weekly: archive Done column, re-prioritise To Do. Healthy boards stay short; long Doing columns signal stalled work.

## Frequently asked questions

<details>
<summary>**What is the origin of Kanban?**</summary>

Toyota production system, 1940s — physical cards signalled when components were needed. Adapted to software (David Anderson, 2010) and now general project management.

</details>

<details>
<summary>**Why limit WIP?**</summary>

Multitasking has a cost. Limiting work-in-progress to 1-3 active cards forces completion, surfaces blockers earlier, and shortens cycle time. Counterintuitive but proven.

</details>

<details>
<summary>**How is Kanban different from Scrum?**</summary>

Kanban: continuous flow, no fixed sprints, WIP-limited. Scrum: fixed sprints (1-4 weeks), commit-and-deliver. Kanban suits ongoing-flow work; Scrum suits project-based delivery.

</details>

<details>
<summary>**Where is my data stored?**</summary>

Local browser storage only. No server, no account, no sync. Export JSON to back up or move to another device.

</details>

<details>
<summary>**Can I add labels and priorities?**</summary>

Yes — colour labels, priority flags, due dates. Filter by label to focus on a category (e.g. "show only #urgent").

</details>

<details>
<summary>**Is a digital Kanban better than physical?**</summary>

Digital wins for: searchability, sync, history. Physical wins for: visibility (always-on wall), tactile satisfaction, team co-location. Many teams use both.

</details>

## Tips

- Keep card titles short — long titles signal the task is too big and should be broken down.
- Archive the Done column weekly; long Done columns add visual noise without value.
- Adopt WIP limits gradually — start with limit = current count + 1, then tighten.
- A card stuck in Doing for 3+ days is a flag — either blocked, too big, or unclear. Investigate.
- Export weekly snapshots; useful for retrospectives and tracking velocity over time.
