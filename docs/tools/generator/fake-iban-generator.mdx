# fake-iban-generator

An IBAN (International Bank Account Number) follows a strict format: country code (2 letters) + check digits (2) + bank-specific identifier (up to 30 chars), with a MOD-97 checksum. The ZTools Fake IBAN Generator produces format-valid IBANs that pass syntax + checksum validation but reference no real bank account. Used for testing form validation, payment-flow QA, schema fuzz testing, and anywhere a real IBAN would be inappropriate (test fixtures in public repos). The generator covers 70+ countries with their specific length and structure rules.

## How it works

1. **Pick country** — Each ISO country code has a specific IBAN length and structure.
2. **Optional bank code** — Some countries allow specifying the bank prefix; the generator fills the rest randomly.
3. **Compute checksum** — MOD-97 algorithm: rearrange string, convert letters to digits, compute mod 97, set check digits so the total ≡ 1 mod 97.
4. **Output** — A format-valid IBAN. Validates against any standard IBAN library — but bank rejects when used for actual transfers (account doesn't exist).

## Frequently asked questions

<details>
<summary>**Are these IBANs safe to use?**</summary>

They're format-valid but reference no real account. Using them to attempt a transfer fails at the bank — no money moves. Safe for testing; never use for real transactions.

</details>

<details>
<summary>**Will they pass my validator?**</summary>

Yes — any IBAN library that checks format + MOD-97 checksum accepts these. Banks doing real-time bank-existence verification reject them, which is the point.

</details>

<details>
<summary>**Can the same fake IBAN match a real account?**</summary>

Statistically yes for very small countries; no for most. The generator picks bank-code + account-number portions randomly. To be safe, only use these in test environments.

</details>

## Tips

- Always label test data clearly as "TEST_ONLY" — a fake IBAN that escapes into production logs can confuse debugging.
- For load testing, generate 1000+ unique fake IBANs — checksum-valid but with high cardinality.
- For UI testing of edge cases, generate IBANs from short (NO, BE) and long (MT, RO) countries to test field width.
- Never use fake IBANs in real banking flows — even though they're harmless, the audit log noise isn't worth it.
