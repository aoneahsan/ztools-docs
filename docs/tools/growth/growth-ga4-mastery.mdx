## Use cases

### Weekly stakeholder summary

A growth lead at a B2B SaaS company needs a Monday email summarizing last week’s GA4 numbers for the leadership channel. Instead of rebuilding the same Explorations every week, they run the acquisition and engagement analyses, then paste the narrative into Slack. The report flags that organic sessions rose while signup-page engagement fell, giving the team a concrete thread to investigate before the standup.

### Diagnosing a checkout funnel dip

An ecommerce manager sees checkout revenue dipping but cannot tell where shoppers leave. They run the funnel and engagement analyses across the last 28 days. The narrative points to a steep drop between add-to-cart and shipping-info on mobile, with a note that one campaign source skews the average. They now have a starting hypothesis to confirm in GA4 Explorations before briefing the dev team.

### Retention check for a content site

A solo newsletter operator wants to know whether new readers come back. They run the retention and segment analyses on their GA4 property. The report describes weak week-two return rates for paid-social visitors versus strong return rates for referral traffic, and suggests segments worth isolating. The operator uses this to decide where to spend the next month’s promotion budget, then verifies the segments themselves.

### Agency client onboarding audit

A freelance analyst onboarding a new client connects the client’s read-only GA4 OAuth and runs the full set of nine analyses in one sitting. The narrative reports become the backbone of a first-week audit document, covering acquisition channels, engagement quality, and retention. Because the client supplies their own LLM key, the analyst keeps usage costs transparent and avoids holding the client’s credentials beyond the encrypted connection.

## How it works

1. **Connect GA4** — Sign in and grant read-only Google OAuth so the tool can query your GA4 property. The connection is scoped to analytics reading only and is encrypted and stored per user.
2. **Add your LLM key** — Paste your own large language model API key. It is encrypted per user and used only to write the report narrative, so model usage bills directly to your provider account.
3. **Pick an analysis** — Choose one of the nine prebuilt analyses, such as acquisition, engagement, retention, funnels, or segments. Each is a fixed prompt designed to pull the relevant GA4 dimensions and metrics.
4. **Set the date range** — Select the reporting window, for example the last 7, 28, or 90 days. The tool fetches the matching data from your property and prepares it for the analysis prompt.
5. **Generate the report** — Run the analysis. Your connected model reads the fetched GA4 data and returns a written narrative highlighting trends, outliers, and possible causes, which you can copy or save for later.
6. **Sanity-check before acting** — Read the report as an interpretation, not a verdict. Confirm the numbers and any flagged drop in GA4 Explorations before you change spend, ship a fix, or brief stakeholders.

## Tips

- Run the same analysis on two date ranges, such as last 28 days versus the prior 28, to make trend changes obvious in the narrative.
- Clean your GA4 first: filter internal traffic, confirm key events, and mark conversions. The reports are only as good as the underlying configuration.
- Connect a stronger reasoning model when you want sharper cause-and-effect language; a smaller model is fine for quick weekly summaries and saves on your provider bill.
- Treat every flagged drop as a hypothesis. Re-create it in GA4 Explorations before you change budget or brief stakeholders.
- For agency work, ask clients to add their own LLM key so usage costs stay on their account and you avoid holding extra credentials.
